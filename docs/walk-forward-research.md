# Fixed-parameter walk-forward research

Milestone 6 now supports chronological, non-overlapping development tests and a
separate final holdout. This is a single-instrument research increment, not full
milestone acceptance or permission to trade.

```bash
uv run python -m services.backtesting.cli \
  --strategy adaptive_pullback \
  --csv reports/generated/m5-final-20261030/data/stock.csv \
  --metadata reports/generated/m5-final-20261030/data/stock.json \
  --walk-forward-config examples/research/walk-forward.json \
  --output reports/generated/walk-forward-stock.json
```

The example uses synthetic data generated by `scripts.research_smoke`. Substitute
validated CSV/metadata for real research; synthetic performance proves software
behavior only. ETF runs still require the matching benchmark files.

Choose the strategy configuration and partition sizes before looking at results.
There is no optimizer or automatic selection. Each development test uses only the
price/benchmark prefix ending at that test, with preceding history for indicator
warm-up. The final holdout is excluded from development tests. Partial trailing
development periods are explicitly reported as unused. Every window resets cash,
uses the existing commissions/spread/slippage and next-open fill model, and
reserves its final bar for liquidation. Strategy and buy-and-hold are both run.
Do not sum window returns or interpret these independent windows as a portfolio.

Reports record input hashes, configuration, source/lockfile hashes and engine
versions. Fixed inputs/configuration reproduce byte-for-byte; output paths cannot
be overwritten. Run start/end dates are rejected in this mode to avoid ambiguous
partition definitions. A CLI cannot prove a person has never viewed the holdout:
freeze the configuration and retain the original report before inspecting it.

Remaining milestone 6 work includes portfolio cash/exposure constraints,
point-in-time news/compliance replay, representative verified history, parameter
selection protocols, Monte Carlo/liquidity tests and the blueprint performance
gates. Historical wins alone do not establish these conditions.
